# Design: ARNO 3.0 inside "Ark Nova - Complete Scripted" (option A)

Status: **draft for review**. The decisions it builds on are in `DECISION.md` §6
("Owner decisions"). References: `MOD_ARCHITECTURE.md` (`Global.lua:<line>`) and
`ARNO_LOGIC.md` (IN-xx/OUT-xx, `[code]/[prose]/[absent]`).

## 1. Goals and non-goals

Goals:
- 1–4 humans plus 0–3 ARNO bots, at most 4 in total. Each ARNO is a real `players` entry in
  an unseated colour.
- ARNO's turn runs automatically. You never move ARNO's pieces.
- ARNO behaves as the helper app computes it (proven by a differential test), with the
  `[prose]`/`[absent]` rules taken from the rulings register (§11).
- Reproducible, undo-safe turns: seeded RNG, all state in the mod's checkpoints.
- **0 ARNOs = the original mod, unchanged in behaviour** (including the official solo
  challenge).
- Published as a new mod version: `dist/ArkNova_Scripted_ARNO.json`.

Non-goals: changing human rules; ARNO for the official solo challenge; any Feuerland
content beyond what the base mod already references.

## 3. Build pipeline (`tools/tts_build.py`)

1. Check that the base save's SHA-256 matches `src/manifest.json` (done). If it doesn't,
   the base mod has been updated: re-extract, rebuild, run the tests.
2. **Bundle** `arno/**/*.lua` into a single Lua block. MoonSharp has no runtime `require`,
   so each module becomes a function in a registry, and a 10-line `arno_require` resolves
   modules lazily with a cache:
   ```lua
   -- BEGIN ARNO BUNDLE (generated by tools/tts_build.py; do not edit)
   local ARNO_MODULES = {}
   ARNO_MODULES["core.rng"] = function(require) ... end
   ...
   local function arno_require(name) ... end
   ARNO = arno_require("main")
   -- END ARNO BUNDLE
   ```
   The bundle adds 2 top-level locals; the chunk currently has 27, against a limit of 200.
   `ARNO` must be a **global** because mod functions defined earlier in the file call it.
3. **Insert** the bundle immediately before `local handler_names = {}`
   (`Global.lua:18045`). At that point the file-local tables (`cnsts`,
   `CHECKPOINT_RESUMES`, `BREAK_RESUMES`, `HexBoard`) are in scope, and ARNO's `on_*`
   button handlers still get the mod's `note_player_interaction` wrapper.
4. **Apply hooks** from `hooks/hooks.json`. Each hook is
   `{id, why, find, replace}` against `Global.lua`, and `find` must match **exactly
   once**, otherwise the build fails and names the hook. A mod update that moves code
   therefore fails loudly instead of silently mis-patching.
5. Set `SaveName` to "Ark Nova - Complete Scripted + ARNO 3.0" and write
   `dist/ArkNova_Scripted_ARNO.json` with the TTS-style serialiser.
6. Validate: compile the generated `Global.lua` in MoonSharp (syntax and local-limit
   check).

**Round-trip proof (done).** `tests/test_tts_roundtrip.py`: extract → build with no
changes gives output **byte-identical** to the original for both saves. That is stronger
than the required semantic identity: floats keep their original text, with CRLF and
2-space indent like TTS. An edit lands only at its manifest path. A mismatched base save is
rejected.

## 4. Hooking strategy: wrappers first, text edits second

The bundle runs at load time after every mod function is defined. Mod code calls globals
by name, so **re-assigning a global function from the bundle hooks every call site without
touching mod code**:

```lua
local orig_panel = create_action_selection_panel
create_action_selection_panel = function(player, only_action, multiplier, hypnosis)
  if ARNO.is_bot(player) then return ARNO.turn.start(player, only_action, multiplier, hypnosis) end
  return orig_panel(player, only_action, multiplier, hypnosis)
end
```

Text edits (`hooks.json`) are used only where behaviour inside a function body must
change. Planned hooks (the final list goes into `CHANGES.md`):

## 5. Turn flow

```
human turn … finish_player_turn → refill, game-end check, break check → after_turn
→ start_player_turn(next)            ← mod: current_player, checkpoint "turn", turns_taken
   └─ create_action_selection_panel(next)
        └─ next.is_arno → ARNO.turn.start(next)
        0. Wait.condition(…, function() return not checkpoint_open end)
           -- nothing in arno_state may change before the checkpoint store
           -- has finished, otherwise the checkpoint would hold post-decision state
        1. panel: "ARNO (Yellow) is playing…" with [Pause] for 2 s
           (auto mode; in manual mode it waits for [Run ARNO turn])
        2. facts = snapshot(next)                      -- pure tables
        3. plan, new_state = core.decide(state, facts, rng)
        4. arno_state = new_state  (in memory; persisted at the next checkpoint)
        5. apply.run(plan) step by step (callbacks; mod Waits)
        6. log + panel: drawn card, slot, every action and its result
        7. ARNO.turn.finish(next) → finish_player_turn(next)   (mod chain continues:
           refill, game-end check, break check, next player)
```

- **Manual fallback trigger:** while `current_player` is an ARNO and no ARNO turn is
  running, the panel shows **Run ARNO turn** to every seated player. It also shows an
  **Auto** toggle, stored in `arno_state`. This covers a failed step, a paused auto run,
  and resuming after load.
- **Several ARNOs in a row** chain through the mod's normal `next_player`.
- **Mid-turn effects** (an ARNO break advance hits 0, an animal triggers human hooks):
  the plan steps call the mod's own primitives, so the mod queues breaks and human prompts
  as it would for a human player. The ARNO turn ends only after its plan is drained, and
  the break runs from `finish_player_turn` as usual. Whether ARNO finishes his card when a
  break triggers mid-turn is ruling R7.
- **Panel/log:** `set_active_panel("arno", xml)`, visible to all seats (it goes through the
  mod's panel system, so re-renders don't wipe it). For each ARNO it shows: the 5 slots
  (active card highlighted, upgraded marked), difficulty, CP debt, tokens on the scoring
  card and notepad, the project-module status (OUT-17), and the last turn's lines
  ("Slot 4 · Build (upgraded): took display card #3 (Cheetah, animal → mat), notepad +1").
  The last 30 log lines are kept in `arno_state.log`. Every line also goes to chat via
  `printToAll`.
- **Physical ARNO action cards:** the mod deals 5 action cards to every `players` entry.
  ARNO's are reused to **show** his slot order and upgrades (`move_action_card_to_front`,
  `*_flipped`). That matches ARNO's own mechanics: Animals starts in slot 1, the used card
  moves to slot 1, and the side flips on upgrade. The core state is the source of truth;
  the cards are only re-synced to it.

## 6. Seeded RNG

- One stream per game: `arno_state.rng = {seed, s}`. The seed is set at setup from
  `os.time()` xor `math.random(2^31)`, and shown in the panel and the log.
- Algorithm: **mulberry32** (32-bit state). It is implemented with `bit32` and a
  16-bit-split multiply, so it is exact with MoonSharp's double-only numbers. In the Node
  harness the same generator replaces `Math.random`, so both sides see the same stream.
- `random()` returns `s / 2^32`, in [0, 1). The ported helper functions keep their exact
  formulas:
  - `rollDice(n) = floor(random()*n)+1`
  - `rollDiceDifferentValue` (recursive)
  - `randomEnum` (index over the enum's value order)
  - lodash `shuffle` (Fisher–Yates with `index + floor(random()*(last-index+1))`; to be
    verified against the installed lodash source in Phase 3)
  - **The call order is part of the contract**, including the unconditional d2 in the
    project pick (ARNO_LOGIC §2.4).
- Undo safety: the RNG state lives in `arno_state` and so in every checkpoint. Rewinding
  to the `"turn"` checkpoint of an ARNO turn and resuming re-runs `start_player_turn` →
  the same facts and the same RNG state → **the same decisions**. Rewinding can't be used
  to re-roll ARNO.
- Every random draw is logged with its purpose (`d4 slot → 3`), so the differential
  harness and you can audit it.

## 7. Pure core vs adapter

**Core contract.** No TTS or mod access. Lua 5.2 subset.

```lua
-- state: per-bot table (§8); facts: snapshot; rng: rng object (mutated)
plan, new_state = decide.turn(state, facts, rng, config)
-- plan = ordered list of steps, each fully resolved, e.g.
--   {kind="appeal", n=4}
--   {kind="partner_zoo", zoo="africa", rolls={4}}
--   {kind="project_support", source="mat", index=2, slot_order={"left","middle","right"}, reward_slot="middle"}
--   {kind="take_display", position=3}
--   {kind="worker", task=3}
--   {kind="token_scoring_card"} / {kind="token_notepad", n=2}
--   {kind="break", n=2}
--   {kind="manual", text="…"}        -- only for unresolved rulings (§11)
new_state = decide.on_upgrade(state, rng)         -- IN-11
side      = decide.bonus_tile(rng)                -- IN-13
draw      = decide.break_draw(state, cards)       -- OUT-15 classification only
cp        = decide.final_cp(state)                -- OUT-16
```

`facts` covers everything the helper asks the human (IN-01..IN-10), read from the table:
- project cards on ARNO's mat;
- board projects with no player cube (neutral cubes ignored) and those ARNO has not
  supported;
- free slots per project;
- available partner zoos and universities, and what ARNO owns;
- ARNO's free workers and the tasks they occupy;
- ARNO's CP (for the "≥ 2 CP → worker" rule);
- display card types;
- sponsor-discard counters.

**Adapter.** It turns a plan into mod calls. ARNO goes through the low-level mutators
(`take_partner_zoo`, `take_university`, `apply_appeal`/`update_rep`/`apply_cp`,
`break_x`, `add_project_to_row`, cube tagging, `display_cards` + `refill_display`,
`donation_slot`) and not through the claim-producing UI entry points
(`get_partner_zoo`, `start_association_action`, …). Any claim the mod still queues for
ARNO (for example map or track bonuses) is resolved by `claims.lua`: keep allowed reward
types, pick by ARNO rule (bonus tile d2, worker over upgrade at ≥ 2 CP), and **pass and
log** anything else.

Animals ARNO takes are stacked on his mat. The adapter adds their icons to his icon
counters (reference values) and calls `apply_hooks` so that **human** "whenever any
player…" effects fire (ARNO_LOGIC §2.7).

## 8. Persistence and rewind

- `arno_state` is a new global listed in `cnsts.saved_globals` (H15), so it is written in
  every checkpoint and restored by `restore_checkpoint`:
  ```lua
  arno_state = { version=1, rng={seed=…, s=…}, auto=true,
    config={ project_module=false, marine_worlds=<mirrors mod> },
    bots={ [color]={ index=1, level=4, extra_cp=0,
      slots={"animals","build",…}, upgraded={…}, last_slot=3,
      tokens_scoring=0, tokens_notepad=0, cp_debt=5,
      mat_projects={guid,…}, sponsor_discards=0 } },
    log={…} }
  ```
- `players[i].is_arno` / `arno_index` go into the saved player fields.
- **No new resume entry is needed**: ARNO turns begin inside `start_player_turn` (through
  the H9 panel wrapper), after the mod's own `"turn"` checkpoint. Resume re-enters
  `start_player_turn` → `create_action_selection_panel` → `ARNO.turn.start`.
- **Ordering rule:** `onSave` serialises `arno_state` during `storeRewindState`. ARNO
  therefore must not advance the RNG or change `arno_state` until
  `checkpoint_open == false` (§5 step 0). Otherwise the checkpoint would hold the
  post-decision state, and a resume would replay a different turn. The same rule applies
  to the break draw in the `"income"` slot. ARNO's break draw runs in the income slot, which is checkpointed
  (`"income"`) the same way.
- ARNO's turn is **atomic from the checkpoint's point of view**. The adapter cancels the
  mod's spacer timer (`cancel_rewind_spacer_timer`) while ARNO plays. If a heartbeat or
  spacer store still lands mid-turn (it carries only the `in-turn:` marker), the mod's
  unresumable panel tells you to rewind one more step. That step reaches ARNO's `"turn"`
  checkpoint, and the turn replays identically.
- **Undo, as you'll use it:** to take back your own move, rewind to your `"turn"`
  checkpoint. Rewinding to ARNO's turn just replays the same ARNO turn. The 2-second
  [Pause] window before an automatic ARNO turn gives you time to rewind first.
- Counter values (appeal/CP/reputation…) live on the counter objects and are restored by
  TTS object state, exactly as for human players.

  ARNO's sponsor discards at setup are counted automatically (IN-01).

## 10. Breaks, game end and scoring

- **Break:** the mod runs it. ARNO skips the hand limit (H12), his workers return with
  everyone else's (12236), and the association board and display refill as usual. In the
  income order, ARNO's slot runs his **break draw**: draw 3, keep the first project card on
  his mat, put the first animal on his mat (icons + human hooks), discard the rest, and
  count discarded sponsors (IN-10).
- **Game end:** the mod's score-based trigger counts ARNO like any player (R9).
- **Final scoring:** ARNO skips the final-scoring discard and the card scoring (H14), and
  gets `clamp(tokens_scoring−2,0,4) + tokens_notepad` CP. The winner comes from the mod's
  `game_winners`, which includes ARNO.

## 12. Testing strategy

- **Python:** extract, round-trip, hook anchors (each `find` matches once in the current
  `src/Global.lua`), and a bundle that compiles.
- **Lua core (headless):** `tools/moonsharp/` is a .NET console app (the .NET 9/10 SDK is
  installed) hosting MoonSharp, the interpreter family TTS uses. A minimal test runner
  (`tests/lua/run.lua`, no busted needed) runs:
  - all ported helper unit tests: `BotActions.spec`, `Cards.spec`, `CardSlots.spec`,
    `ProjectModuleTracker.spec`, `getDifficultyLevel.spec`;
  - RNG known-answer tests;
  - state round trip.
- **Differential harness:** `tests/harness/` runs thousands of random scenarios (level,
  slot states, upgrades, token counts, project counts, rerolls) with `Math.random`
  replaced by mulberry32(seed), writes JSON, and the Lua core must match exactly. Two
  levels of evidence:
  - **`services/*` and `NavigationState.getBotRound`: the original TypeScript, unchanged.**
  - **Component-level dice** (`BotActions.vue` display d6, `GainPartnerZoo/University.vue`,
    `BonusTile.vue`, `ActionCards.vue upgradeCard`, `PickConservationProject.vue`): these
    are Vue component methods and can't run headless. The harness carries a TypeScript
    transcription, with each function citing the source file and lines.

  Matching call order is a **Lua-vs-harness reproducibility rule**, not equivalence to
  the app, which rolls unseeded when a page renders. The harness needs **Node ≥ 20.19**
  (you have 20.18).
- **Adapter:** Lua tests against a fake mod (fake `players`, display, projects and
  primitives recording calls).
- **In TTS:** your `TESTING.md` checklist covers setup variants (1H+1A, 1H+2A, 2H+1A,
  0 ARNO, official solo), a full game with breaks, game end, scoring, rewind in the middle
  of an ARNO turn, and save/load.

## 13. Risks and mitigations

| Risk | Mitigation |
|---|---|
| A bot colour has nobody seated: `Player[color].getHandObjects` / `deal` behaviour | ARNO never uses a hand (H7, H8, H12). **Probe** to confirm no mod path reads the bot's hand; any that does gets a wrapper. |
| Mod paths that assume human panels (draft, income, discards, map ready) | Each one is enumerated in MOD_ARCHITECTURE §15 and has a hook (H5–H8, H12, H14). TESTING covers each. |
| Mod updates | Anchored hooks fail the build loudly. Prefer wrappers. Re-run the tests. |
| Mid-turn async (mod Waits) vs ARNO plan | Plan steps run sequentially with completion callbacks. The turn finishes only after the last callback. |
| MoonSharp numerics | Integer-safe PRNG, known-answer tests run in MoonSharp itself. |
| `[absent]` rules | Rulings register with explicit constants and panel markers. |
| ARNO's break draw runs in the income slot; an animal he stacks can fire human hooks, which open human prompts in the middle of the income phase | Run the draw before handing over to the next income player. TESTING.md has a case for it. |
| ARNO wrappers called with `only_action`/`multiplier`/`hypnosis` (human-only mechanics) | Log and ignore for bots. A test asserts it can't happen in ARNO games. |
